# KartDrift Offline — 原客户端离线研究

分析、反编译与修改原客户端，使其在停服后本地运行。独立创建的项目，不是 fork。目标包括《跑跑卡丁车：漂移》和 2004 年起的 PC《跑跑卡丁车》，以 iOS 为首要平台，同时研究 macOS 与 Android。

## 当前状态

- Drift：已保留 iOS 2.71.1 原 App 和缓存资源；另建诊断副本，不修改保留的原安装。
- Android：已从用户授权的 Flip4 保留 2.71.1 原安装的 5 个 APK 分包和 26 个缓存 PAK，约 4.7 GB 归档，两端 SHA-256 一致；这些文件不随源码发布。
- 地图入口补丁已在原进程验证：当前世界为 `License_T01`，已生成原版驾照模式、玩家控制器和赛车对象；11 个关卡层已载入，原版组件报告子关卡加载完成。
- 显式设置 `?players=1` 后，原版自由练习 HUD、触屏按钮和部分场景可见；原版驾驶、相机、漂移与音效组件已生成。默认零玩家会使驾驶组件初始化停在较早阶段。
- 资源查询与模型应用补丁已在真机验证：原版 `Kartbody_Practice` 与 `Mesh_Practice` 加载并显示，原版速度表有非零速度，车辆位置随原引擎运行而变化；触屏方向键输入后，赛车朝向从约 −17° 变为 108°。
- 验证设备为 iPadOS 16.1 真机，尚未在 iPhone 验证。角色显示、场景与相机仍有问题；漂移和完整 AI 比赛尚未验证，不能视为可交付的完整离线版本。
- 原版：已获取并静态提取 2004 年 PC 演示客户端，81 个文件、65 个 RHO 档案；已开始反编译原程序。演示客户端不代表完整历代服务端和游戏功能。
- **两个原客户端均未通过离线可玩验收。**

验收要求：真实原客户端运行，本地单人驾驶与漂移、和多名 AI 完整进行竞速赛及道具赛。训练场、启动画面和资源查看均只是中间步骤。完整需求见 [requirements.json](requirements.json)。

## 分析工具

`tools/` 包含我们编写的 PAK 检查、资源读取、ARM64 反汇编辅助、iOS 内存诊断和独立测试副本准备工具。Python 依赖见 `requirements.txt`。这些工具用于用户自己的保留文件和授权设备；具体版本地址与二进制偏移需要核对。

客户端版本资料参考[公开保存资料](https://clientlover.tistory.com/13)。原始客户端、资源、解密后的执行文件、设备日志及地址仅保存在本机，不随源码发布。

## 已验证载入地图的 iOS 入口补丁

已定位正式版 `UGameInstance::StartGameInstance` 将地图解析器输入置为空字符串的指令。`tools/enable_ios_map_override.py` 在核对整个启动函数 SHA-256 后，只修改一条指针保存指令，使地图解析器使用 `FCommandLine::Get` 返回的地址；其他空字符串回退保持原样。

此补丁不等于完整离线恢复。修改会使原签名失效，需要重新签名独立副本。`tools/prepare_ios_probe.py --enable-commandline-map` 可将补丁应用到诊断副本；`--restore-preserved-metadata` 可附带本地保留的少量资源版本文件，在副本自己的沙盒中恢复。资源文件和修改后的二进制不上传仓库。

`tools/ghidra/DecompileTargets.java` 用于对本机二进制的指定地址范围反编译；输出保存在本机。地址采用 Ghidra 导入后的虚拟地址，ELF 需要注意加载器的重定位。对已确认不会返回的调用（例如栈保护失败入口），可传入 `--noreturn=地址`，避免反编译器将后续函数错误并入当前函数。

`tools/read_kartdrift_task.c --inspect` 可只读检查保留的 iOS 2.71.1 进程：命令行、当前世界、原版对象、反射属性与完整组件集合。`--inspect 对象地址` 可读取指定对象；`--threads` 可采样线程调用栈。地址与布局只针对已分析版本，不能直接套用其他客户端。

`tools/enable_ios_asset_load.py` 是独立的资源加载诊断补丁：核对原版函数的哈希，将主资源对象查询中的一次 `ResolveObject` 调用改为原引擎的 `TryLoad`。可选 `--load-kart-mesh` 会额外核对车辆模型应用函数，再修改该函数内的一次查询调用；该组合已在保留版本的测试副本中加载原版练习车并响应转向输入。它会改变资源查询行为，可能产生同步加载停顿；不代表已恢复完整游戏。

`tools/android_mcp.py` 可连接用户授权的 Android MCP。连接配置通过 `ANDROID_MCP_CONFIG` 指向本地 JSON，或放在忽略的 `runtime/android-device.json` 中，字段为 `url`、`token`，可选 `session`。令牌、设备地址和会话不放入公开源码。

## 已停止的替代游戏实验

`core/`、`platform/`、`scripts/` 和对应构建测试来自此前误解需求后编写的独立卡丁车原型。它不是原客户端的恢复版本，其运行和测试结果不代表本项目恢复成功。用户已明确要求回到原客户端逆向，因此停止这条替代路线；保留代码便于审查历史。
